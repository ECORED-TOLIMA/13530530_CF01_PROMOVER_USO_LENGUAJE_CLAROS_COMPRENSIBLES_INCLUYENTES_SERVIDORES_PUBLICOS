Propósito
Principio general

La maquetación se realiza por bloques

A

Diseño aprobado

El PDF o archivo de diseño define la composición visual esperada.

B

Contenido fuente

TemaX.vue aporta los textos y la secuencia temática.

C

Biblioteca institucional

Los componentes existentes definen estructura, comportamiento y estilo.

Primero se reutiliza. El CSS personalizado se reserva para necesidades que la biblioteca no resuelva.

Antes de comenzar

Insumos mínimos

  • PDF, XD o diseño aprobado
  • Textos definitivos por tema
  • Imágenes organizadas y nombradas
  • Menú y numeración confirmados
  • Paleta institucional
  • Biblioteca de componentes
  • Glosario y referencias
  • Introducción, síntesis y actividad

Si falta un insumo que pueda cambiar la estructura o el contenido, se reporta antes de avanzar con ese bloque.

Lenguaje común

Cómo solicitar un ajuste

Bloque: nombre, clase o fila donde inicia Estado actual: qué está correcto y qué está incorrecto Resultado esperado: cómo debe quedar Componente sugerido: componente o referencia aprobada Qué debe cambiar: estructura, color, imagen, margen o contenido Motivo: razón institucional, visual o funcional

Indicar qué está correcto evita que una corrección estructural modifique contenido, imágenes o colores ya aprobados.

Soluciones institucionales
Criterios transversales

Reglas que deben cumplirse siempre

Estructura

  • Títulos internos en h5
  • Márgenes .mb-4 y .mt-4
  • Último párrafo con p.mb-0
  • Responsive con retícula Bootstrap

Accesibilidad

  • Imágenes no numeradas: alt=""
  • Figuras: alternativa descriptiva
  • Mismo alt en versión móvil
  • Fondos cargados con require_src
Calidad transversal
Evitar reprocesos

Lo que no debemos hacer

  • Modificar bloques no señalados
  • Cambiar contenido durante un ajuste visual
  • Dejar muestras duplicadas
  • Crear CSS sin revisar la biblioteca
  • Simular componentes con clases parecidas
  • Ignorar la vista móvil
  • Acumular ajustes sin compilar
  • Dejar decisiones sin documentar
Disciplina de implementación
Punto de control

¿Cuándo está listo un tema?

  • Contenido completo y correcto
  • Imágenes y rutas verificadas
  • Sin muestras duplicadas
  • Componentes institucionales correctos
  • Títulos y márgenes normalizados
  • Accesibilidad aplicada
  • Escritorio y móvil validados
  • CSS sin uso eliminado
  • Compilación exitosa
  • Decisiones documentadas
  • Revisión por bloques cerrada
  • Aprobación confirmada
